Transcodage distribué

…

Activé : le plugin capte les transcodages de lecture et les conversions qu'Emby lance, avec les réglages et profils d'Emby, et les confie aux workers disponibles ; sans worker, Emby les traite sur le serveur comme d'origine. Désactivé (ou plugin désinstallé) : Emby fonctionne exactement comme d'origine. Aucun redémarrage n'est nécessaire ; après une mise à jour d'Emby, le plugin se reconfigure seul au démarrage.

Connexion des workers

…

Par défaut https://0.0.0.0:8097 : les workers se connectent directement en TLS (certificat généré par le plugin, vérifié par les workers). Derrière un reverse proxy HTTPS : écoute en http://127.0.0.1:8097 et adresse publique https://… du proxy. Avec Emby sous Docker, publiez ce port. Adresse du serveur pour les workers : nom d'hôte ou adresse IP par laquelle les PC joignent ce serveur, placée dans le code d'association en TLS direct (vide : adresse réseau local détectée ; à renseigner sous Docker ou si le code d'association contient une adresse injoignable). Les nouveaux réglages s'appliquent tout de suite ; associez à nouveau les workers si l'adresse publique change.

Signalement des échecs

…

Quand une conversion échoue (assemblage rejeté par le contrôle, worker en échec sur une tranche, conversion rendue à Emby), le plugin ouvre ou complète une issue sur le dépôt du projet pour que l'erreur soit corrigée. Envoyé : les versions (plugin, Emby, système du serveur, workers décrits par leur GPU et leur version), le message d'erreur sans chemin, les caractéristiques techniques de la source (conteneur, codecs, résolution, images/s, durée, HDR, pistes audio) et le déroulé de la conversion. Jamais envoyé : chemin, nom de fichier, titre, adresse, nom de domaine, nom de PC, de worker ou d'utilisateur. La source est désignée par un code anonyme, relié au fichier dans le journal d'Emby de ce serveur seulement. Au plus 5 envois par jour.
